# Мой лучший агент

Платформа для поиска пропавших людей, животных и вещей: заявки «Потерял» и «Нашёл» с фото и точкой на карте, автоматический подбор совпадений, анонимный чат, экстренные оповещения по радиусу и реестр ценностей.

Первая очередь по ТЗ (Приложение №1 к договору №71). Веб-приложение и PWA (устанавливается на телефон, работает с push-уведомлениями), русский и английский интерфейс, светлая и тёмная тема, админ-панель.

## Возможности

**Для пользователей**
- Заявки о пропаже и находке в три категории: люди, животные, вещи. Пошаговый мастер: описание, до 5 фото, место на карте, дата, контакт.
- Заявки о людях публикуются только после проверки модератором. Заявку о несовершеннолетнем подаёт только законный представитель. Когда человек найден, его личные данные скрываются.
- Карта и список заявок: фильтры, поиск по тексту, кластеры меток, радиус «от меня».
- Автоматический подбор совпадений между потерянным и найденным (категория, вид, расстояние, дата, приметы) с уведомлением обеим сторонам.
- Анонимный чат по заявке: контакты не раскрываются, можно отправить фото и точку на карте.
- Экстренное оповещение (SOS): push людям и волонтёрам в радиусе 1–5 км, запуск после проверки модератором.
- Реестр ценностей: предметы с серийными номерами и приметами. При краже предмет отмечается «украдено», и любой может проверить вещь по номеру.
- Личный кабинет: заявки, сообщения, сохранённые, зона оповещений, платежи, баллы и статусы волонтёра, семейный аккаунт, поддержка, удаление аккаунта.
- Вход без пароля, по одноразовому коду на e-mail или телефон.

**Для команды**
- Админ-панель: статистика и выгрузка в Excel, модерация, экстренные оповещения, жалобы, все заявки, пользователи и роли, волонтёры и партнёры, поддержка, запросы на удаление, платежи и тарифы, справочники, переводы и тексты, истории, журнал писем и SMS, журнал действий.
- Раздел «Система»: резервное копирование и карточка «Готовность к работе», где видно, что подключено, а что нет.
- Роли: пользователь, волонтёр, партнёр (организация), модератор, администратор.

**Платные тарифы** (оплата картой РФ или через СБП, чек по 54-ФЗ, автопродление сохранённой картой): расширенный реестр ценностей, продвижение заявки, тариф для организаций.

## Технологии

| Часть | Что используется |
|---|---|
| Сервер | Node.js 22.13+, Express 4, встроенный SQLite (`node:sqlite`) |
| Интерфейс | без фреймворка: ES-модули, свой шаблонизатор, PWA (service worker, manifest), Web Push |
| Карта | Leaflet 1.9.4 и Leaflet.markercluster 1.5.3 (лежат в проекте), тайлы OpenStreetMap |
| Почта и SMS | nodemailer (любой SMTP), SMS.ru |
| Оплата | ЮKassa API v3 |
| Документы и отчёты | pdfkit (PDF правовых документов), exceljs (выгрузка в Excel) |
| Тесты | `node:test` и Playwright (Chromium) |

Сайт не загружает ничего со сторонних CDN: скрипты, стили и шрифты отдаются самим сервером. Content Security Policy разрешает внешние адреса только для тайлов карты.

## Быстрый старт

Нужен **Node.js 22.13 или новее**.

```bash
git clone https://github.com/Victor-Northcode/mybestagent.git
cd mybestagent
npm install
npm start          # http://localhost:3000
```

При первом запуске в тестовом режиме создаётся база `data/app.db` с демо-данными: пользователи, заявки, чаты, совпадения.
Чтобы начать с чистой базы, остановите сервер и удалите папку `data/`.

Режим разработки с перезапуском при изменениях: `npm run dev`.

## Запуск в работу

1. **Сервер в РФ** (требование 152-ФЗ), Node.js 22.13+. Перед Node.js нужен HTTPS-прокси: nginx или Caddy.
2. **Настройки.** Скопируйте `.env.example` в `.env` рядом с `package.json` и заполните. `npm start` читает `.env` сам.
   - `NODE_ENV=production`, `BASE_URL=https://ваш-домен`.
   - `ADMIN_EMAIL` — e-mail администратора. Войдите на сайт с этим адресом, и роль «Администратор» назначится автоматически.
   - **E-mail**: `SMTP_URL` любого SMTP-сервиса (Яндекс 360, Mail.ru для бизнеса, Unisender Go и т. п.) и `MAIL_FROM`.
   - **SMS**: `SMSRU_API_ID` из личного кабинета SMS.ru (и `SMSRU_FROM`, если согласовано имя отправителя).
   - **Оплата**: `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY` (ЮKassa → Интеграция → Ключи API), ставка НДС `YOOKASSA_VAT_CODE`.
     В ЮKassa → Интеграция → HTTP-уведомления укажите `https://ваш-домен/api/payments/webhook`, события `payment.succeeded` и `payment.canceled`.
   - **Реквизиты оператора**: `LEGAL_NAME`, `LEGAL_INN`, `LEGAL_OGRN`, `LEGAL_ADDRESS`, `LEGAL_EMAIL` (или админка → «Переводы»).
3. **Чистая папка данных.** Используйте новую `data/` или укажите `DATA_DIR`. База с тестового стенда содержит демо-пользователей и заявки.
4. **Запуск**: `npm start`. Что не настроено, сервер пишет в журнал при старте. То же видно в админке → «Система» → «Готовность к работе».
5. Оператору персональных данных нужно подать уведомление в Роскомнадзор (ст. 22 152-ФЗ).

Как всё работает в рабочем режиме:
- **Вход.** Код уходит письмом или SMS и никогда не показывается на экране. Если канал не подключён, пользователь видит, что вход этим способом недоступен. Если отправка не удалась, появляется ошибка «не удалось отправить код».
- **Оплата.** Пользователь переходит на страницу ЮKassa (карта или СБП; чек 54-ФЗ формирует ЮKassa). После возврата сайт ждёт подтверждения. Тариф подключается только после того, как сервер сам запросил статус платежа у ЮKassa и сверил сумму: само уведомление доказательством оплаты не считается. Карта сохраняется для автопродления. Если банк отказал в списании, автопродление выключается, и пользователь получает уведомление.
- **Без ключей ЮKassa** кнопки оплаты недоступны, рядом есть пояснение. Тестовая страница оплаты работает только в тестовом режиме.
- **Журнал писем и SMS** со статусами (отправлено / ошибка) — админка → «Исходящие». Одноразовые коды в журнале скрыты.

## Переменные окружения

Полный пример с комментариями — в [`.env.example`](.env.example).

| Переменная | Назначение |
|---|---|
| `PORT` | порт (по умолчанию 3000) |
| `NODE_ENV=production` | рабочий режим: код входа не показывается на экране, нет демо-данных и тестовой оплаты. За HTTPS-прокси cookie получают флаг secure и включается HSTS |
| `BASE_URL` | публичный https-адрес сайта: ссылки в письмах и push, возврат после оплаты, превью ссылок, адрес в документах |
| `ADMIN_EMAIL` | e-mail администратора: при входе с ним роль «Администратор» назначается автоматически |
| `SMTP_URL`, `MAIL_FROM` | отправка e-mail (коды входа, уведомления) через SMTP |
| `SMSRU_API_ID`, `SMSRU_FROM` | отправка SMS через SMS.ru |
| `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`, `YOOKASSA_VAT_CODE`, `YOOKASSA_TAX_SYSTEM` | приём оплаты через ЮKassa |
| `LEGAL_NAME`, `LEGAL_INN`, `LEGAL_OGRN`, `LEGAL_ADDRESS`, `LEGAL_EMAIL` | реквизиты оператора для документов (то же можно задать в админке → «Переводы», ключи `legal.op.*`) |
| `DATA_DIR` | где хранить базу, фото и резервные копии (по умолчанию `./data`) |
| `UPLOAD_QUOTA_MB` | лимит места под фото на одного пользователя (по умолчанию 200 МБ). Фото, не прикреплённые ни к чему, удаляются через сутки |
| `VAPID_PUBLIC`, `VAPID_PRIVATE`, `VAPID_SUBJECT` | ключи web-push. Если не задать, ключи создаются автоматически и сохраняются в `data/vapid.json` |
| `TRUST_PROXY` | кому доверять заголовок X-Forwarded-For (по умолчанию `loopback` — прокси на этом же сервере) |
| `SEED_DEMO` | `1` — создать демо-данные и в рабочем режиме (только для демонстрационного стенда) |
| `DEV_OTP` | `1` — показывать код входа на экране и на удалённом тестовом стенде. В рабочем режиме код не показывается никогда |

## Внешние сервисы

- **E-mail и SMS** — `server/services.js` (SMTP через nodemailer, SMS.ru). Без ключей в тестовом режиме сообщения только пишутся в журнал «Исходящие».
- **Оплата** — `server/yookassa.js` (API ЮKassa v3). Без ключей в тестовом режиме открывается тестовая страница `#/pay/:id`.
- **Карта** — тайлы OpenStreetMap, библиотеки лежат в `public/vendor/`. На самой карте подписей нет. Указание источника, обязательное по лицензии OpenStreetMap («Картографические данные © участники OpenStreetMap»), находится в подвале сайта. При большой нагрузке правила tile.openstreetmap.org не подходят: понадобится свой тайл-сервер или коммерческий провайдер. Адрес тайлов меняется в функции `tiles()` в `public/js/core.js`.

## Правовые документы

Четыре документа на русском и английском, тексты — в `server/legal.js`:

| Документ | Страница | PDF |
|---|---|---|
| Пользовательское соглашение (публичная оферта) | `#/legal/terms` | `/api/legal/terms.pdf` |
| Политика конфиденциальности (152-ФЗ) | `#/legal/privacy` | `/api/legal/privacy.pdf` |
| Согласие на обработку ПДн (ст. 9 152-ФЗ) | `#/legal/consent` | `/api/legal/consent.pdf` |
| Согласие на распространение ПДн (ст. 10.1 152-ФЗ) | `#/legal/publication` | `/api/legal/publication.pdf` |

- Все документы со скачиванием PDF — на странице `#/legal` (ссылки есть в подвале и в кабинете → «Настройки»).
- PDF собирается на сервере из того же текста, что и страница: A4, нумерация пунктов, «стр. X из Y», блок реквизитов. Английская версия — с параметром `?lang=en`.
- При регистрации согласия открываются поверх формы, кнопка «Прочитал(а) и принимаю» ставит галочку. Согласие на распространение даётся при публикации заявки.
- Изменили текст — поменяйте дату редакции `EDITION` в `server/legal.js`. Заменить документ целиком без правки кода можно в админке → «Переводы», ключ `legal.text.<документ>`.
- Сроки хранения из политики соблюдаются автоматически: раз в сутки удаляются истёкшие коды входа, сессии старше 30 дней, журнал и исходящие старше года.

## Безопасность и хранение данных

Вся база — один файл SQLite `data/app.db`. Рядом лежат `secret.key` (ключ сервера), `vapid.json` (ключи push), `uploads/` (фото) и `backups/` (копии).
Пока сервер работает, рядом временно есть файлы `app.db-wal` и `app.db-shm`. Удалять их нельзя: при остановке сервера журнал переносится в `app.db`.

- Паролей нет. Токены сессий хранятся только как SHA-256, коды входа — как HMAC с ключом `secret.key`, который лежит отдельно от базы.
- Все запросы к базе параметризованы. Включены внешние ключи, `secure_delete` (удалённые данные затираются), `trusted_schema=OFF` и проверка целостности при запуске.
- CSRF-защита для изменяющих запросов, ограничение частоты запросов кодов и входов, строгая Content Security Policy, HSTS в рабочем режиме.
- Доступ к папке `data/` есть только у владельца процесса. Папка не раздаётся веб-сервером и исключена из git. При переносе на другой сервер копируйте её целиком, вместе с `secret.key`.

**Резервные копии** создаются автоматически раз в сутки в `data/backups/`, хранятся 14 последних. Сделать копию вручную: `npm run backup` или кнопка в админке → «Система».

## Тесты

```bash
npm test           # всё: API, рабочий режим и браузерные E2E (~2 мин)
npm run test:api   # только API
npm run test:prod  # рабочий режим: чистая база, вход по SMS, оплата ЮKassa
npm run test:e2e   # интерфейс в Chromium: мобильная вёрстка 360 px, язык, вход, мастер, кабинет, чат, карта, админка, доступность (axe)
```

Тесты поднимают отдельный сервер на свободном порту с временной базой, рабочие данные в `data/` не затрагиваются.
В тестах рабочего режима SMS.ru и ЮKassa заменены локальной заглушкой с тем же API: в интернет тесты не ходят и денег не списывают.
Для E2E один раз установите Chromium: `npx playwright-core install chromium`.
